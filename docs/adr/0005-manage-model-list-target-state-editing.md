# 管理模型列表：目标状态编辑取代补充／重建双入口

状态：2026-10-05 用户确认采纳；**已实现**（2026-10-05，commit `767484b^..5afe522`：T1–T6＋两轮评审修复，测试 211/211 通过）。完整规则以[双 profile 设计规格](<../design/2026-10-03-dual-profile-auth-and-models.md>)§4.1/§4.2 为准；真机人工验证清单（M01/M02/M15/M16/U01）尚未执行，发版、部署、真实授权或重启仍需另行授权。

## 背景

[ADR 0004](<0004-safe-model-management-and-profile-isolation.md>) 确立的「默认补充＋显式重建」双入口要求用户先理解后端分类学（两操作在追加/对齐、保留/清除定制、缓存/live 三轴上的差异）才能选对入口；同时系统不存在局部删除能力——删掉几个过时模型必须全量重建并清除全部定制。2026-10-05 用户梳理补充弹窗时提出「全表勾选＋待删除＋终态预览」的统一视图，经对抗式讨论确认为语义升级而非 UI 重排，并裁决合并双入口。

## 决策

单一操作「管理模型列表」（目标状态编辑）：勾选集合即期望终态，应用时目标＝勾选集合；新增与移除由勾选与在列集合的差集导出。风险不再由入口按钮决定，而由实际 diff 决定：

- 移除类变更（removed>0）强制 live 账号证据；升级确认 ⟺ removed>0 ∨ 勾选「清除全部定制」 ∨ 空目标；纯新增/无变化单次确认且 24h 缓存可用；服务端 apply 物化时强制。
- 被保留模型的定制全保留；被移除模型的定制随模型消失；「清除全部定制」仅在存在可清除定制时可选，存在仅继承覆盖时禁用并说明。
- 待删除候选（账号未报告／目录无法解析）默认不勾选＝删除提案，可重新勾选挽留；降级证据下锁定保留并拒绝删除类 apply。
- 快捷动作「对齐账号与目录」仅设定勾选状态；目录条目维度总是包含。

本决策替代 Q1（双入口）与 Q15（不可解析项无条件保留）；「缺失≠意图」的哲学保留，兑现方式从「一律保留」改为「提案可见＋可挽留＋确认升级」。Q5（候选初始不勾选）与 Q6（重建语义）并入新语义。

## 考虑过的替代方案

- 仅重排展示不改语义：待删除名不副实（补充从不删除），重建保留，选门问题原样。
- 删除走独立高级入口：两个入口的问题没有解决，只是换位置。
- 任何删除沿用重建语义清除全部定制：取消一个勾导致所有参数蒸发，放大破坏且反直觉。
- 「清除定制」也强制 live：定制是本地配置事实，与账号证据无关，无依据。
- 提供「跳过目录写入」开关：目录只增不覆盖，跳过无收益只有误关风险。
- 应用时才拒绝缓存证据下的删除（现状式）：把证据不足暴露在最晚时刻，改为自动 live 升级（闩锁每预览会话一次）。

## 后果

正面：补齐局部删除能力；默认动作从 no-op 变为「对齐漂移」；`inherited-overrides-unclearable` 对整个操作的阻断消失（仅约束可选复选框）；用户不再需要学习双入口差异。

代价与风险：破坏性从具名危险按钮移入常规弹窗，依赖三道护栏（可挽留、降级锁定、确认升级）兜底；协议 diff 形状、状态机确认门控、弹窗布局、双语文案与验收矩阵（M01/M02 重写，新增 M15/M16）均需改动；词汇表两术语退休。ADR 0004 的目录只增、双通道、事务恢复、profile 隔离裁决全部继续成立，仅「默认补充＋显式重建入口」的手段被本决策替代。
